Reverse engineering case study

XGIMI Elfin BLE Wake

I reverse engineered the Bluetooth Low Energy wake signal used by an XGIMI Elfin projector remote, then replayed a safe wake advertisement from an ESP32.

What Worked

  • Captured the remote's power-button advertisement with ESP32 and macOS witness tools.
  • Identified manufacturer ID 0x0046 and the stable wake payload tail.
  • Confirmed that ESP32 raw advertising could wake the projector without spoofing the remote address.
  • Documented the safer non-connectable advertisement path that preserved the original remote pairing.

What Did Not Work

Native macOS Bluetooth advertising reported success at the API layer, but witness captures showed it did not emit the required manufacturer data. That negative result became part of the protocol model instead of being hidden as a failed attempt.

Why It Matters

The project is a practical example of protocol investigation: capture real device behavior, separate facts from guesses, test safer replay paths, and leave a handoff that another engineer can continue without rereading a long chat log.

The working repo is currently private because it contains device-specific captures and hardware notes. This page summarizes the public-safe engineering story.
